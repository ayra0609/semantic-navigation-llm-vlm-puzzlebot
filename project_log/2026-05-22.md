# 2026-05-22

## Supervisor Meeting - End-to-End Demo and Evaluation Review

Meeting with supervisor to present the current state of the semantic navigation system on
PuzzleBot. The focus was to demonstrate that the complete text-command-to-robot-motion
pipeline is now integrated and to review the first structured set of real-device
experiments.

---

## 1. End-to-End Demonstration

Presented a live end-to-end demo of the full pipeline:

```text
Natural-language command
-> LLM intent/object extraction
-> SLOT command representation
-> Grounding DINO object grounding
-> Depth Anything V2 distance estimation
-> ROS2 navigation control
-> PuzzleBot physical movement
```

The demo showed that the system can receive a user command, extract the target object,
identify the corresponding object in the camera stream, estimate its relative distance, and
drive the PuzzleBot towards the target.

This directly addressed the previous concern that the individual modules had been tested
separately but the complete LLM -> SLOT -> Grounding DINO -> ROS2 loop still needed to be
shown on the real robot.

---

## 2. 25-Trial Experimental Data Presented

Presented 25 real-robot experiment trials collected under the current evaluation setup.
The purpose was to move from anecdotal demonstrations to a more rigorous evaluation with
repeatable conditions and measurable outcomes.

The dataset covered:

- Fixed command set for navigation requests
- Repeated trials using the same target-object categories
- Real-device logs from PuzzleBot runs
- Success/failure outcomes for each trial
- Latency breakdown across the main modules
- Observed failure cases and recovery behaviour

Metrics discussed:

| Metric Area | Notes |
|---|---|
| Intent extraction | Time for LLM to parse the natural-language command into a target label |
| Perception | Grounding DINO detection latency and Depth Anything V2 distance-estimation latency |
| Network | Jetson/PC/HPC communication delay during remote inference |
| Navigation | Total time from command issue to arrival or failure |
| Outcome | Whether the robot reached the intended target without collision or wrong-object selection |

The 25-trial result table was used to show early evidence of system reliability, while also
highlighting that the evaluation criteria still need to be made more precise before final
reporting.

---

## 3. Discussion: Next Optimisation Directions

The meeting discussion focused on improving both the system behaviour and the evaluation
rigour.

### Evaluation Improvements

- Make test conditions explicit, including lighting level, room layout, object placement,
  command set, and number of repetitions per condition.
- Report statistics across trials, including mean, standard deviation, and possibly
  confidence intervals for latency and success rate.
- Define pass/fail criteria more precisely:
  - correct target selected
  - no collision
  - final stopping distance within acceptable range
  - task completed within a realistic time threshold
  - system handles temporary detection loss without unsafe behaviour
- Include robustness checks:
  - paraphrased commands
  - distractor objects
  - repeated trials under the same condition
  - different lighting conditions

### System Optimisation

- Improve object-detection accuracy for chair-like targets. In current trials, chairs and
  chair-related objects can be visually ambiguous because of thin legs, partial occlusion,
  and similarity to nearby furniture. The next step is to tune prompts, thresholds, and
  evaluation examples specifically for chair targets.
- Add obstacle detection during navigation. If an obstacle is detected in the robot's path,
  the robot should stop immediately and return a clear status such as
  `"Obstacle detected. Navigation stopped."` instead of continuing forward.
- Improve close-range stopping behaviour, especially where monocular depth estimates become
  noisy or overestimated near the target.
- Reduce alignment oscillation caused by low-rate Grounding DINO detections and stale
  heading errors.
- Investigate lightweight tracking between Grounding DINO frames to improve heading updates
  without requiring full detector inference every control cycle.
- Continue separating latency by module so the main bottlenecks are clear:
  LLM parsing, SLOT conversion, perception inference, network transfer, and ROS2 actuation.
- Improve failure handling and recovery behaviour when the target is temporarily lost,
  incorrectly detected, or blocked by distractor objects.

---

## Outcome of Meeting

The supervisor confirmed that the project now has a demonstrable end-to-end system rather
than only isolated LLM, VLM, and ROS2 components. The 25-trial dataset is a useful starting
point for evaluation, but the next stage should focus on making the experimental protocol
more rigorous and the results easier to defend statistically.

The immediate priority is to continue expanding the real-device trial set while refining the
pass/fail definition, robustness tests, and latency reporting.
